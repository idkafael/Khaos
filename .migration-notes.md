# Notas de Migração: py-cord → disnake

## Data: 26/10/2025

## Motivo da Migração
Modais do py-cord apresentavam falhas persistentes ao clicar em "Enviar", mesmo após múltiplas correções. Disnake oferece implementação mais estável e API superior para modais.

## Principais Diferenças

### Modais
- **py-cord**: `ui.InputText` + `add_item()` + `on_submit()` + acesso via `self.children[0]`
- **disnake**: `ui.TextInput` + `components=[]` + `callback()` + acesso via `interaction.text_values[custom_id]`

### Type Hints
- `discord.Interaction` → `disnake.ModalInteraction` (para modais)
- `discord.Interaction` → `disnake.MessageInteraction` (para buttons/selects)
- `discord.ApplicationContext` → `disnake.ApplicationCommandInteraction`

### Nomenclatura
- Convenção: `ctx` → `inter` (mais descritivo)

## Problemas Encontrados

### 1. InputText vs TextInput
- py-cord usa `ui.InputText`
- disnake usa `ui.TextInput`
- Solução: Todos os modais usando `ui.TextInput` com `components=[]`

### 2. on_submit vs callback
- py-cord usa `on_submit(self, interaction)`
- disnake usa `callback(self, interaction)`
- Solução: Renomeado em SetupMessageModal e CouponInputModal

### 3. children[0] vs text_values
- py-cord acessa via `self.children[0].value`
- disnake acessa via `interaction.text_values.get("custom_id")`
- Solução: Usando `text_values` com `custom_id` em modais refatorados

### 4. ApplicationContext vs ApplicationCommandInteraction
- py-cord usa `discord.ApplicationContext`
- disnake usa `disnake.ApplicationCommandInteraction`
- Solução: Substituído em todo bot.py (403 ocorrências)

### 5. PermissionOverwrite
- py-cord usa `discord.PermissionOverwrite`
- disnake usa `disnake.PermissionOverwrite`
- Solução: Substituído em todo ticket_manager.py

### 6. sync_commands()
- py-cord usa `await bot.sync_commands()` ou `await bot.sync_commands(guild_ids=[...])`
- disnake usa `await bot.sync_all_commands()` ou `await bot.sync_commands_force([guild_id])`
- Solução: Substituído em bot.py
